# 협력 게임 실험 웹앱

진행자 한 명과 참가자 네 명이 각자 기기에서 같은 방에 접속하는 프로토타입입니다. 별도 패키지를 설치하지 않고 Node.js만으로 실행됩니다.

## 내 컴퓨터에서 실행하기

1. Node.js가 설치된 컴퓨터에서 `server.js`가 있는 폴더를 엽니다.
2. 터미널에서 `node server.js`를 실행합니다.
3. 진행자는 해당 컴퓨터에서 `http://localhost:3000`을 엽니다.
4. 진행자가 방을 만들고 표시된 6자리 코드를 네 명의 참가자에게 전달합니다.
5. 같은 Wi-Fi에 있는 참가자는 진행자 컴퓨터의 내부 IP 주소를 사용해 `http://내부IP:3000`으로 접속하고 방 코드와 이름을 입력합니다. 예: `http://192.168.0.12:3000`. Windows에서는 `ipconfig`를 실행해 무선 LAN 어댑터의 IPv4 주소를 찾을 수 있습니다.
6. 네 명이 모두 들어오면 진행자가 조건을 선택하고 실험을 시작합니다. 각 참가자는 한 회차에 한 번 제출합니다. 네 명의 입력이 모이면 결과가 자동으로 표시됩니다.

Windows에서 같은 Wi-Fi 접속이 안 되면 컴퓨터 방화벽이 Node.js의 로컬 네트워크 연결을 막고 있을 수 있습니다.

## 공개 사이트로 배포하기

`render.yaml`은 Render용 배포 설정입니다. GitHub와 Render 계정이 필요합니다.

1. [GitHub](https://github.com/signup)와 [Render](https://render.com/)에 가입합니다.
2. GitHub에서 새 저장소를 만듭니다. 저장소 이름은 예를 들어 `cooperation-game`으로 정합니다.
3. 이 `outputs` 폴더의 `index.html`, `server.js`, `render.yaml`, `README.md` 파일을 저장소의 최상위에 올립니다. GitHub 저장소 화면의 **Add file → Upload files**에서 파일들을 선택하고 **Commit changes**를 누르면 됩니다.
4. Render에서 **New → Blueprint**를 선택하고 방금 만든 GitHub 저장소를 연결합니다. `render.yaml` 설정을 확인하고 **Deploy Blueprint**를 누릅니다.
5. 배포가 끝나면 Render 서비스 화면의 `onrender.com` 주소를 친구들에게 공유합니다. [Render 첫 배포 안내](https://render.com/docs/your-first-deploy)와 [Blueprint 안내](https://render.com/docs/infrastructure-as-code)를 참고하세요.

GitHub 저장소는 비공개로 만들어도 Render에 연결할 수 있습니다. 코드를 웹으로 배포하는 일과 실험에 참가하는 일은 별개이며, 친구들에게는 Render가 만든 웹 주소만 보내면 됩니다.

무료 웹 서비스는 15분간 요청이 없으면 일시 중지되고, 무료 인스턴스의 로컬 파일은 재시작/중지 후 보존되지 않습니다. 현재 앱의 방 상태도 메모리에 있으므로 서버가 중지되거나 재시작되면 방과 기록이 사라집니다. [Render 무료 서비스 한계](https://render.com/docs/free)를 참고하세요. 발표회에서 쓰는 동안은 모든 참가자의 페이지를 열어 두고, 중요한 기록은 진행자가 회차 종료 때마다 CSV로 저장해야 합니다. 안정적인 장기 운영은 데이터베이스 연동과 유료 상시 서버가 필요합니다.

## 실험 흐름

- A: 비공개, 보너스 없음
- B: 공개, 보너스 없음
- C: 비공개, 보너스 있음
- D: 공개, 보너스 있음
- 기여량은 참가자별 0–10 정수입니다.
- `S`는 네 명의 기여 합, `R = 1.5 × S ÷ 4`입니다.
- 개인 최종 점수는 `10 − 개인 기여량 + R + 보너스`입니다.
- C·D에서 `S ≥ 24`이면 각 참가자에게 3점 보너스를 줍니다.
- 진행자는 매 회차마다 다음 조건을 정할 수 있습니다. 완료 회차의 기록은 진행자 화면에서 볼 수 있고 CSV로 내려받을 수 있습니다.
- 공개 조건은 제출한 기여량을 모든 접속자에게 보여줍니다. 비공개 조건은 개인 기여량과 타인의 점수를 참가자에게 보여주지 않고, 본인에게만 본인 점수를 보여줍니다. 진행자는 연구 진행과 CSV 저장을 위해 비공개 조건의 개인 기록도 볼 수 있습니다.

## 한계

- 방과 회차 기록은 서버 프로세스 메모리에만 있습니다. 서버를 종료하거나 재시작하면 방과 기록이 사라집니다.
- 공개 URL로 배포하면 서로 다른 네트워크에서 접속할 수 있습니다. 이 폴더의 앱은 아직 공개 URL로 배포되지 않았습니다.
- 접속한 브라우저 탭은 1.2초 간격으로 서버 상태를 확인합니다. 연결이 끊겼다가 복구되면 같은 탭에서 다시 동기화됩니다.
- 네 명의 참가자만 방에 들어갈 수 있으며 진행자는 별도 역할입니다. 진행자는 참가자 자격으로 참여하지 않습니다.

안정적으로 사용하기 전에는 서버 재시작에도 방/회차를 보존하는 데이터베이스, 재접속 복구, 방 만료와 백업을 추가하는 것이 좋습니다.
